# QA-1 + UX-2 Operating Layer

Date: 2026-06-09

## Purpose

This layer turns the site from a growing resource list into a maintainable query service. It answers three operating questions:

- Which county and need areas are thin?
- Which source problems are true broken links versus temporary transport failures?
- Should the next data batch be broad or targeted?

## Artifacts

Generated by `scripts/build_operational_artifacts.py`:

- `data/coverage-matrix.json`
  - County-by-need coverage matrix.
  - Status values include `local-strong`, `local-entry`, `local-needs-confirmation`, `central-ok`, `central-fallback`, `private-only`, and `gap`.
- `data/source-health-summary.json`
  - Summary of record/source counts, hard warnings, transient warnings, confidence counts, and source-level counts.
- `data/batch-gate.json`
  - Decision object for whether to open a broad next batch.
  - Current recommendation: targeted only.

## Current QA-1 Result

The current matrix has 198 county-by-need pairs:

- 154 pairs are already `local-strong` or `central-ok`.
- 44 pairs need observation or targeted strengthening.
- 9 high-score candidates are listed for future targeted work.

The top candidates are mostly local medical or health-insurance support gaps where central fallback exists but local details are still thin.

## UX-2 Changes

Frontend changes:

- Added a 60-second guided query path in the filter panel.

- Added a public-facing source-health and coverage summary.
- Added batch-gate candidate buttons that can jump into a filtered search.

## Batch Gate Rule

Do not open a broad Batch 7 only to increase record count. Open a targeted batch only when at least one of these is true:

- `data/freshness-report.json.summary.warnings > 0`
- a high-score coverage candidate appears in `data/batch-gate.json`
- a validated common user phrase returns no useful result
- a high-risk group has only central fallback and no local detail
